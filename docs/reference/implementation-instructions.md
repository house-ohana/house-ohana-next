# フェーズ1：平時ブランチの実装

## 1-1. 最初にやること（コードを書く前）

以下を確認して提案してください。**私の承認まで編集しないこと。**

1. 既存の `/diagnosis` の実装構成（ルート、コンポーネント、設問データの持ち方）
2. 既存の結果ページのURLクエリ仕様（`v=1` の実装箇所、許可値照合の処理）
3. 今回追加するファイルの配置案と、**再利用する既存コンポーネント名**
4. **既存の配色トークンの一覧**（globals.css / Tailwind設定で実際に使われている色）

## 1-2. 目的

3分整理ナビは現在、**今まさに対応が必要な方**を想定して作られています。
そこに、**今は大きな問題がなく、これからに備えたい方**の経路を追加します。

新しい概念を足すのではなく、**同じ軸・同じカテゴリのまま、時間の位置だけを変えます。**

## 1-3. 入口

`/diagnosis` の冒頭に、次を表示します。

> **今すぐ対応が必要な方だけでなく、今は大きな問題がなく、これからに備えたい方も利用できます。**

> **今の状況に近いものを選んでください**
> - 今すぐの大きな対応は必要なく、これからに備えたい　→ `m=pre`
> - 入院・退院・介護など、今まさに対応が必要　→ `m=post`（既存）

**トップページを経由しないと使えない設計にしないこと。**
`/diagnosis` および平時側の入口へ**直接アクセス可能**にしてください。

## 1-4. 回答者の定義（冒頭に表示）

> このナビでは、これからの暮らしについて考える方を「**ご本人**」と表します。
> **ご本人自身でも、ご家族や身近な方でも**回答できます。

- `who = self`（本人）／ `family`（家族・身近な方）を選択させる
- **「お子さん」という語は使わない。**すべて「**ご家族や信頼できる方**」

## 1-5. カテゴリ（5分類）

1. 本人の希望と医療
2. お金
3. 住まい
4. 支える人
5. 希望を知る人・動く人

**カテゴリを色で区別しないこと。**見出し・アイコン・ラベル・余白で区別します。

## 1-6. 設問（最大15問・条件付き表示）

設問と選択肢は `docs/reference/navi-result-mapping.md` の第1節に定義されたものを使用します。
そのうえで、**以下の条件分岐**を実装してください。

- **T1** は `Q1=a`（希望がある）のときだけ表示する
- **T4** は支える可能性のある方が具体的に存在する場合だけ表示する
- **前の回答によって成立しない設問は、表示せず、回答コードもURLに追加しない**

**T5は次の内容に差し替えます。**

> 通帳・保険証券・重要な書類の場所を、書面やデータにまとめていますか
> `a` まとめている ／ `b` 口頭でのみ伝えている ／ `c` まとめていない

## 1-7. 結果画面

```
[該当時のみ] 冒頭の一文
　↓
A．今、確認できていること　　（件数を表示してよい）
　↓
B．これから確認・話し合うこと　（上位3件のみ・件数は表示しない）
　　「上から1つだけで十分です。全部を今日決める必要はありません。」
　　［そのほかを見る］（折りたたみ）
　↓
末尾：共通の相談導線
　↓
共有・保存・印刷
```

### 絶対原則

**事実を反射するだけ。判定・診断・スコアは一切出さない。**

- ◎ 「保険を確認してから5年以上経っています」＝ **事実**
- ✕ 「保障が不足しています」＝ **判定**
- ✕ 点数・達成率・レーダーチャート・信号色（赤／黄）による危険表示

## 1-8. 末尾の共通相談導線

**保険を上位に操作しないこと。**優先順位は仕様書のとおりとし、
**全分野共通のボタンを1つだけ**末尾に置きます。

> ［**どこに相談すればよいか整理する**］

問い合わせ画面でテーマを選択（複数選択可）：
医療・介護／お金・保険／住まい／家族の支え方／手続き

「保険を見直す」「おすすめを聞く」とは書かないこと。

## 1-9. 問い合わせへの引継ぎ（重要）

- 引き継いでよいのは**利用者が選んだ相談テーマのみ**
- **設問回答・結果文・回答コード・共有URLを自動添付しない**
- 診断結果の送信は、**利用者が明示的に選択した場合だけ**

## 1-10. 共有・保存・印刷

**ボタンは全利用者共通で3つ**：`結果を共有する` / `保存する` / `印刷する`
（利用者の状況によってボタンを出し分けないこと）

**共有前に表示：**
> 共有用URLには、今回選んだ回答から作成された結果が含まれます。共有する相手をご確認ください。

**共有ボタンを押した本人に、次を併記：**
> 「**先に整理しておきました**」と伝えられます。

**共有された側に最初に表示する1行：**

| 回答者 | 文言 |
|---|---|
| `who=self` | ご本人が、これからの暮らしについて整理した結果です。 |
| `who=family` | ご家族や身近な方が、ご本人のこれからについて整理した結果です。 |

**印刷仕様**
- **A4・1枚のみ。A5版は作らないこと**（半分に折ればA5サイズになるため不要）
- 収める内容：Bの上位3件／Aの最大5件／6件目以降は「そのほか○件確認できています」／
  相談領域／作成日
- **60〜80代が読む前提。本文の文字を小さくしないこと。**
  入りきらない場合は、文字を縮めるのではなく**掲載件数を減らす**
- 用紙サイズ指定はA4のみ。ブラウザの印刷ダイアログに依存する複雑な指定をしない

## 1-11. 技術要件

- Next.js App Router + TypeScript + Tailwind CSS
- `searchParams` は Promise として `await` で取得
- クエリ値は許可値と照合し、不正値でも壊れないこと
- **`m` が無い既存URLは `m=post` として扱う**（後方互換。既存の共有URLを壊さない）
- 新しく生成するURLには必ず `m=pre` または `m=post` を含める
- URLには**短い許可コードのみ**（質問文・自由記述を含めない）
- 結果ページは `noindex`（robots.txtでのクロール禁止はしない）
- OGP・タイトルに診断内容を含めない
- **既存サイトの配色・余白・角丸をそのまま継承し、新しい色を追加しない**
- **文字サイズのみ、後述「共通要件：可読性・アクセシビリティ」に従って引き上げる**（全ページ共通）
- パッケージ操作は `pnpm.cmd` を使用

# フェーズ3：トップページの対象拡張と文章トーンの見直し

> フェーズ2の承認後に着手。**修正候補を一覧提示 → 承認 → 編集**の順を守ること。

## 3-1. トップページの対象範囲を広げる

平時の利用者にも自分に関係があると伝わるようにします。

**ページタイトル案**
> これからの暮らしと、家族の選択を整理する｜House OHANA

**ヒーロー上部**
> 病気や介護が始まる前の備えから、今まさに対応が必要な場面まで

**ヒーロー本文案**
> 元気なうちに考えておきたいことも、退院、介護、住み替えなど今すぐ対応が必要なことも。
> House OHANAは、ご本人の希望、ご家族の生活、お金、医療・介護、住まい、手続きに関する
> 状況を整理し、次に確認することを見つけるお手伝いをします。

**次の2文は必ず維持：**
> 人生の後半も、好きな場所で、自分らしく。
> その願いを、家族だけの負担にしない。

> ※ トップに「これからに備えたい方／今まさに対応が必要な方」の**選択を最初に置かないこと。**
> 　 経路の分岐は `/diagnosis` の冒頭で行います。トップの訴求は弱めません。

## 3-2. 表現の方針

**使用する表現**：一緒に整理します／まず確認できることから始めます／
今すぐすべてを決める必要はありません／ご本人とご家族が選べる状態をつくります／
専門職へ相談するときの質問を整理します

**原則として避ける表現**：強い断定／来訪者を責める表現／不安を強める表現／
営業上の内部用語／「できていないこと」を欠点として示す表現／
「このままでは困る」「今すぐ行動するべき」などの行動圧力

**ただし**、免責事項・プライバシーポリシー・緊急時の案内では、必要な制限を削除しないこと。

## 3-3. 「House OHANAが決めないこと」の扱い

見出しは次のいずれかに変更してよい：
> House OHANAがお手伝いする範囲 ／ 専門的な判断が必要なこと

本文案：
> House OHANAは、特定の結論や商品を代わりに選ぶ場ではありません。
> ご本人とご家族が納得して選べるよう、状況、選択肢、専門職へ確認する質問を整理します。

一覧は名詞表現へ：
これからの住まい方の最終決定／施設や住み替え先の選定／不動産の売却・賃貸に関する契約／
保険商品の選択や契約／医療・介護サービスに関する専門的な判断／
法律・税務・登記に関する専門的な判断

一覧の後：
> これらについて判断が必要になった場合は、どの分野へ何を確認すればよいかを整理します。

## 3-4. ★重要：非仲介の明示は削除しないこと

次の一文は、**運営方針ページまたは免責事項に、明確な形で必ず残してください。**

> House OHANAが売却や賃貸をお勧めしたり、取引を仲介したりすることはありません。

トップページ側の表現は柔らかくしてよい：
> 「残す」「管理する」「貸す」「売る」は、それぞれ選択肢の一つとして整理します。
> 具体的な契約や手続きについては、利用者ご自身が選んだ専門事業者へご相談いただきます。

**「適切な専門分野へつなげます」という表現は使わないこと**（紹介と読めるため）。

## 3-5. 医療・介護に関する説明

> 医療や介護について専門的な確認が必要な場合は、医療機関や介護・福祉の専門職へ
> 相談するための質問や論点を整理します。

専門職向けページ・免責事項には、従来の明確な業務範囲の説明を残してよい。

## 3-6. 内部用語を公開画面に出さない

コード・仕様書・管理資料でのみ使用し、**公開画面に表示しない**：
平時ブランチ／事後ブランチ／身寄りなし判定／保険導線／見込み客／リード／
優先ロジック／マッピング／スコア／コンバージョン

公開画面での言い換え：
平時 →「これからに備えたい方」／事後 →「今まさに対応が必要な方」／
身寄りなし →「身近に頼れる方がいない場合」／導線 →「次に確認できること」／
判定結果 →「整理した結果」

## 3-7. 直接的な文面の確認

次をプロジェクト全体で検索し、**強く見えないか個別に確認**：
決めない／行いません／対応しません／できません／売る／仲介／判断／犠牲／負担／
必要です／すべき／早めに／今すぐ／問題／困る／認知機能が低下する前に／頼れる人がいない

**一律削除しないこと。**必要な説明は残し、来訪者を急かす・責める・怖がらせる文章だけを修正します。

## 3-8. デザインは変えない

新しい色・フォント・アイコン・レイアウト・アニメーションを追加しない。
既存の配色・余白・見出し階層・カードデザインを維持する。
**ただし文字サイズと行間は例外**とし、「共通要件：可読性・アクセシビリティ」に従う。
文章量でレイアウトが崩れる場合は**文章を短くする。デザインを変えない。**

# 共通要件：可読性・アクセシビリティ（全フェーズ適用）

> 「文字が小さくて読めない」という声が実際に出ています。**全フェーズで最優先の要件**として扱ってください。

## 方針

このサイトの読者は、**高齢の本人と、その家族に限られます。**
通常サイズを維持すべき別の読者層はいません。

したがって、**切替トグルを付けるのではなく、既定値そのものを引き上げます。**
（トグルは「見つけて押す」手間が要り、その一手間を越えられない人こそが最も困っているため）

## 数値基準

| 項目 | 基準 |
|---|---|
| 本文 | **18〜20px（1.125〜1.25rem）**。16px以下の本文を作らない |
| 補足・注記 | **16px以上**。「小さい文字」用のクラスを新設しない |
| 見出し | 本文の1.3〜1.6倍（大きくしすぎると1画面の情報量が減る） |
| 行間 | **1.7〜1.8**（日本語は英語より広く必要） |
| 1行の長さ | 全角**20〜25文字**で折り返す（`max-width` で制御） |
| タップ領域 | **最低48px四方** |
| 文字の太さ | **`font-weight: 400` 以上**。300などの細字を本文に使わない |

## 実装上の必須事項

- **サイズ指定は `rem` を使う。`px` 固定にしない。**
  端末側で文字を大きく設定している利用者は多く、`px` 固定はその設定を無効化してしまいます。
  **これを守るだけで大半が解決します。**
- viewport に **`user-scalable=no` / `maximum-scale` を追加しない**（既存の指定も確認すること）
- 既存の `px` 指定があれば `rem` に置き換え、**置き換えた箇所を一覧で報告**する

## コントラスト

加齢で低下するのは視力だけでなく**コントラスト感度**です。文字を大きくしても薄ければ読めません。

- 本文のコントラスト比は **7:1 を目標、最低 4.5:1**
- 補足テキストを薄いグレー（`#999` 等）に**しない**
- **既存の文字色・背景色は変更しないこと**（現行の組み合わせは十分なコントラストがあります）

## ナビ画面固有

- 選択肢は**ラジオボタンではなく全幅のカード**にし、**枠全体をタップ領域**にする
  （小さい丸を正確に押すのは、手の震えや乾燥がある年代には難しい操作です）
- **1画面1問**を維持する
- 進捗表示（例：3／12）を入れる。ただし残り件数で急かす文言は付けない

## 文字サイズ切替について

**付けなくてかまいません。**付ける場合のみ、以下を守ってください。

- 設置は**ページ最上部**（フッターでは見つけられません）
- ラベルは「**文字を大きくする**」（「表示設定」では伝わりません）
- 選択は `localStorage` 等で記憶してよい（表示の設定であり、個人情報ではありません）
- **「高齢者モード」等の名称にしない**（そう名乗ると使うのをためらう人がいます）

## 印刷にも同じ基準を適用

印刷時の本文も小さくしないこと。
入りきらない場合は、**文字を縮めるのではなく掲載件数を減らす**（フェーズ1-10と同じ原則）。

## 報告事項

1. 変更前後の文字サイズ・行間の一覧
2. `rem` に置き換えた箇所の一覧
3. レイアウトが崩れた箇所と、その対処

# 4. マッピング仕様の修正点（実装前に反映すること）

`docs/reference/navi-result-mapping.md` に対して、以下を適用してください。

## 4-1. 「身近に頼れる方がいない」の条件を限定

**特別表示の条件は `Q7=c` または `Q9=c` のみ。**
`T1=d` `T2=d` `Q6=c` `Q10=c` は該当させない
（「相手が決まっていない」と「身近に頼れる方がいない」は別の状態です）。
